# 音乐标题重写器

将用户的音乐意图转换为新的、面向生成的结构化字幕。通过渐进式披露查找有用的参考：路由到小型风格家族，比较紧凑卡片，然后仅读取选定的完整模板。

仅使用自然语言推理和本地文本文件。不要执行脚本、构建数据库、计算嵌入、调用外部 API 或扫描所有 1000 个模板。

## 输入

接受：

- `Caption`：必需的自然语言音乐描述。
- `Lyrics`：可选的歌词，包含带方括号的段落或控制标签。
- 额外约束：可选的长度、格式、排除项或创意方向。

仅使用歌词文本推断广泛的情感上下文和叙事强度。永不引用、转述、总结或复制歌词内容。仅将带方括号的标签视为可执行的结构、音乐、人声或制作指令。

## 工作流程

按顺序遵循这些阶段：

1. 从输入构建私有音乐简报。
2. 解析显式约束和段落本地指令。
3. 阅读 [references/genre-router.md](references/genre-router.md)。
4. 阅读一个主家族索引，仅在有用时阅读一个辅助家族索引。
5. 选择最多三个具有不同角色的参考。
6. 仅阅读这些卡片命名的完整模板文件。
7. 设计连贯的逐段时间线。
8. 渲染并验证新字幕。

除非用户请求诊断，否则不要暴露音乐简报、路由选择、分数或模板 ID。

## 构建音乐简报

仅提取支持或合理推断的值：

- 宏观流派、子流派以及文化或市场风格
- 情绪和情感弧线
- 大致速度、节拍和律动
- 人声存在、性别、音域、音色和演绎方式
- 核心乐器和制作纹理
- 段落结构和特定段落变化
- 空间特性和显式排除项

在内部将每个值分类为 `explicit`、`tagged`、`inferred` 或 `unspecified`。

当更广泛的描述足够时，不要发明精确的调性、BPM、人声音域、旋律音程或制作技巧。

保留显式的器乐请求。不要添加人声。如果人声存在未指定，选择用户描述和最近风格家族支持的保守处理方式。

## 解析约束

应用此优先级：

1. 显式用户要求和排除项。
2. 来自歌词标签的段落本地指令，仅在该段落内。
3. 来自用户 Caption 的强烈暗示。
4. 选定参考的特性。
5. 保守的音乐默认值。

段落标签可以改变其本地编曲，而不替换歌曲的全局流派。当标签与用户的硬性排除项冲突时，保留该排除项。

当两个显式指令冲突时，如果意图仍然清晰，优先选择更具体和后面的指令。否则做出最小的音乐连贯妥协。

永不静默地反转显式人声性别、器乐要求、速度限制、必需乐器或禁止元素。

## 渐进式披露路由

首先阅读流派路由器。选择：

- 一个主家族用于明确的流派请求
- 一个主家族和一个辅助家族用于显式融合
- 最多两个可能的家族用于模糊流派
- 当仅有情绪或意象时，选择通用流行和民谣家族

使用流派、律动、乐器和文化上下文作为比通用形容词（如 `emotional`、`epic`、`dark` 或 `modern`）更强的路由信号。

仅阅读路由器选定的家族索引。不要检查每个家族索引、重建全局目录或扫描每个模板文件名。

## 选择参考

使用此优先级比较选定家族索引中的卡片：

1. 流派和子流派兼容性。
2. 显式要求和排除项。
3. 律动和速度兼容性，包括可能的半速或双倍速关系。
4. 人声配置。
5. 乐器配置。
6. 情绪和情感弧线。
7. 制作特性。

对直接冲突应用强惩罚。优先选择紧密的音乐家族，而非仅共享情绪词汇的卡片。

选择最多三个具有不同职责的参考：

- `Foundation`：最接近的整体身份、律动和创作语言。
- `Modifier`：请求的次要流派、人声特性、文化色彩或制作纹理的最佳来源。
- `Arrangement`：段落发展、能量轮廓、过渡和乐器生命周期的最佳来源。

当请求简单时，使用一到两个参考。不要为了达到三个而选择弱匹配。

## 安全使用模板

使用 Foundation 获取广泛的音乐身份，仅使用 Modifier 获取其匹配的维度，仅使用 Arrangement 参考获取时间线逻辑。

不要继承不支持的细节，如模板的确切调性、BPM、歌手、乐器、情感故事或段落顺序。

不要复制句子、独特短语或模板的完整结构。围绕用户简报综合新的字幕。

## 规划时间线

当存在用户段落标签时，围绕它们构建。否则仅选择适合该风格的段落，例如：

`Intro → Verse → Pre-Chorus → Chorus → Verse → Chorus → Bridge → Final Chorus → Outro`

对于每个包含的段落，说明什么进入、退出、变化或增强。保持乐器行为连续，使过渡在音乐上合理。

创建可读的能量弧线，而非静态设备列表或一堆制作术语。

## 输出合同

除非用户明确要求其他语言，否则用英文编写最终字幕。

返回确切的这三个顶级标题，按此顺序：

### 全局元数据

包括流派和子流派、速度、情感进程以及整体音效和制作概况。仅在显式或强烈证实时使用精确 BPM；否则使用范围或定性速度。仅在显式或音乐上有用时包含调性和音阶。

### 人声细节

对于人声音乐，描述主唱配置、音色、音域、演绎、和声或伴唱，以及克制的人声效果。

对于器乐，说明该曲目是器乐，并识别承担主旋律角色的乐器或纹理。

不要发明歌词主题或复制歌词内容。

### 编曲

将歌曲描述为逐段时间线。解释主要和次要乐器生命周期、律动发展、过渡、装饰、纹理和空间效果，仅在相关时说明。

优先选择具体的音乐变化而非装饰性散文。默认约 250-450 个英文单词，除非用户要求其他长度。

不要包含歌曲标题、曲目 ID、选定模板 ID、推理跟踪或复制的歌词行。

## 机器可读输出

仅在明确请求时返回 JSON 或 JSONL。包括原始输入和 `rewritten_caption`。仅在明确请求时包括路由诊断或选定模板 ID。

除非用户特别要求，否则永不在机器可读输出中包含完整模板内容。

## 返回前验证

验证：

- 每个显式用户约束都被保留
- 每个可操作的段落标签出现在匹配的段落中
- 没有引用、转述或总结的歌词内容、标题或曲目 ID 出现
- 器乐请求保持器乐
- 人声性别没有被矛盾
- 流派和本地修饰符共存连贯
- 三个必需标题都存在
- 编曲遵循可读的时间线
- 乐器有连贯的进入、变化和退出
- 精确 BPM、调性和技术细节没有被捏造
- 没有复制模板句子或完整模板结构
- 字幕足够具体以指导生成，而不会成为论文

当任何检查失败时修订一次，然后仅返回更正后的结果。

## 静态库维护

保持库完全基于文本。添加模板时：

1. 在 `templates/` 下添加一个完整的 Caption 文件。
2. 在流派路由器链接的恰好一个家族索引中添加一个紧凑卡片。
3. 在该卡片中记录兼容的辅助家族，而不是复制它。
4. 确认卡片 ID 与模板文件名匹配，且其路径存在。
5. 更新该索引中的家族计数。

不要添加脚本、生成的目录、嵌入、向量存储、数据库或外部服务配置。
